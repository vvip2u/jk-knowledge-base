# 元数据规范

> 每篇笔记的 frontmatter 该填什么，以本文为准。缺一维即体检 FAIL。

## 一、落地形式

- 位置：每个 `.md` 文件**开头**的 YAML frontmatter，两条 `---` 之间；
- 键名一律**英文小写**，值用中文；
- 五个维度缺任意一个 → 体检报错；本行业专有字段统一加 `x_` 前缀，与通用字段分开。

## 二、五个维度与字段

### ① 身份（唯一识别）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | string | 全库唯一，格式见《编号与溯源链》；不回收、不复用 |
| `title` | string | 「对象 + 动作/场景 + 结果」，如《销售团队 Q3 大客户交付标准复盘》 |

### ② 权属（谁负责）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `author` | string | 原始提供者 |
| `owner` | string | 后期维护责任人；未定填「待定」 |

### ③ 时效（可信度）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `created` | date | `YYYY-MM-DD` |
| `updated` | date | 每次实质修改都要改 |
| `status` | enum | `draft` / `review` / `active` / `deprecated`，禁止自造 |
| `review` | string | 复审周期，默认 `180d`，合规类 `90d` |

### ④ 安全（可见性）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `confidentiality` | enum | `public` / `internal` / `restricted` / `confidential`，禁止自造 |
| `rbac` | string[] | 可读角色组；不区分就写 `[]` |

### ⑤ 血缘（追溯性）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `source` | string | 原始链接、会议纪要编号、合同号，或上一环编号 |
| `relations` | string[] | 关联的 SOP、父级项目、同主题其他层次资产 |

### 关系与状态（也在 core 清单里）

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `project` | string | 所属项目 `P001`；无则空 |
| `ref_hypothesis` | string | 关联假设编号；假设卡自填自身编号 |
| `ref_experiment` | string | 关联实验编号；实验卡自填自身编号 |
| `version` | string | `v1.0` 形式 |
| `confidence` | enum | `高` / `中` / `低`，见《置信度标准》 |
| `conf_src` | string[] | 高/中档必填：支撑它的库内编号 |
| `conf_why` | string | 低档必填：为什么这么判断、缺什么才能升级 |
| `l1` | string | 标签第一层，单值，见《标签体系》 |
| `l2` | string[] | 标签第二层 |
| `l3` | string[] | 标签第三层 |

## 三、可直接照抄的样例

```yaml
---
id: DOC-HR-2026-003
title: 销售团队 Q3 大客户交付标准复盘
author: 张三
owner: 客户成功部-李四
created: 2026-07-02
updated: 2026-09-20
status: active
review: 180d
confidentiality: internal
rbac: [销售, 客户成功]
source: "2026Q3 交付复盘会纪要 #M-2026-071"
relations: ["SOP-大客户交付v3", "案例-A客户上线事故"]
project: P001
ref_hypothesis: H-2026-001
ref_experiment: E-2026-003
version: v1.0
confidence: 高
conf_src: [R-2026-014, E-2026-003]
conf_why: ""
l1: 客户成功部/售后交付
l2: [实施顾问, 突发事故应急]
l3: [避坑指南, 交付中]
---
```

## 四、常见错误

| 错误 | 后果 |
| --- | --- |
| 只写 `title` 不写 `id` | 无法被索引与引用，等于孤岛 |
| `status: 已完成` | 自造枚举值，过滤与统计全部失效 |
| 低置信度却 `status: active` | 自相矛盾，体检 FAIL |
| 把行业字段写成 `client` | 与通用字段混淆，必须用 `x_client` |
| 复制同一份笔记到多个目录 | 违反单一归属，编号会撞车 |
