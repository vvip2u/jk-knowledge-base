# 编号与溯源链

> 编号前缀、流转主链、`relations` 怎么写，以本文为准。
> 一句话：**层次靠目录分开，链条靠编号串起来。**

## 一、编号前缀表（唯一权威，禁止自造）

| 前缀 | 含义 | 主存放目录 | 示例 |
| --- | --- | --- | --- |
| `R` | 原始资料 Raw | `02_原始资料库` | `R-2026-014` |
| `S` | 研究报告 Study | `03_研究与洞察` | `S-2026-006` |
| `H` | 假设 Hypothesis | `04_思考与假设` | `H-2026-001` |
| `E` | 实验 Experiment | `05_验证与证据` | `E-2026-003` |
| `K` | 知识卡 Knowledge | `06_知识与模型` | `K-2026-002` |
| `D` | 决策 Decision | `10_决策与复盘` | `D-2026-007` |
| `RT` | 复盘 Retro | `10_决策与复盘` | `RT-2026-004` |
| `P` | 项目 Project（跨年不重置） | `09_项目与运营` | `P001` |
| `SK` | 岗位技能 Skill（跨年不重置） | `11_岗位技能库` | `SK-001` |
| `DOC` | 其他（系统/通用/原子卡片） | 任意 | `DOC-SYS-2026-001` |

- 格式 `<前缀>-<四位年>-<三位序号>`；项目与 SKILL 用三位序号且不按年重置；
- 序号年内递增，**不复用、不回收**；
- 未在上表的资产一律用 `DOC`，确需新前缀先改本表再使用。

## 二、流转主链（常见路径，不是强制顺序）

| 环 | 目录 | 动作 | 产出 |
| --- | --- | --- | --- |
| 1 | `02_原始资料库` | 采集原始信息（访谈、问卷、竞品存档） | `R-` |
| 2 | `03_研究与洞察` | 清洗加工，形成研究发现 | `S-` |
| 3 | `04_思考与假设` | 提出**可证伪**的判断 | `H-` |
| 4 | `05_验证与证据` | 设计并执行实验，留下证据（含反面证据） | `E-` |
| 5 | `06_知识与模型` | 提炼**带适用条件**的可复用认识 | `K-` |
| 6 | `08_作品与成果` / `09_项目与运营` | 应用知识，产出正式版本 | 作品版本 / `P` |
| 7 | `10_决策与复盘` | 记录决策与事后复盘，生成下一轮假设 | `D-` / `RT-` |

**允许回退**：任何一环都能退回前一环补资料、改假设、重做实验；
回退产生的是**新的编号**，旧编号保留。

## 三、`relations` 字段的标准用法

| 字段 | 方向 | 填什么 |
| --- | --- | --- |
| `source` | 上溯一层 | 直接依据的原始出处或上一环编号（`R-2026-014` / 「访谈第 7 场」） |
| `ref_hypothesis` | 指向假设 | 本卡服务于 / 来自哪条假设；假设卡自填自身编号 |
| `ref_experiment` | 指向实验 | 本卡由哪个实验支撑；实验卡自填自身编号 |
| `relations` | 自由双向 | 项目、父级文档、同主题其他层次资产 |
| `project` | 横向 | 所属项目 `P001` |

一条完整的链必须能**反向走通**：

```
D-2026-007（定价决策）
  ← H-2026-001（假设：客户愿付 499/月）
  ← E-2026-003（实验：10 家试用）
  ← S-2026-006（研究：痛点频次）
  ← R-2026-014（原始：20 家访谈逐字稿）
```

## 四、五条纪律

1. **编号唯一**：全库唯一，体检查重，重复即 FAIL；
2. **编号不回收**：删除或归档后不复用，避免旧引用指向新内容；
3. **单一归属**：一份内容只有一个主存放位置，靠编号与标签跨目录关联，禁止复制到多个目录；
4. **假设不删改**：被推翻后保留原文（含当时依据与预期），正文写明替代假设编号；
5. **决策不改写**：不得按后来的结果回改决策记录，后来的认识写进复盘。

## 五、断链检查

- 体检会核对 `ref_hypothesis` / `ref_experiment` 指向的编号在库内是否存在；
- 指向不存在 → WARN，季度维护时补齐或修正；
- 归档区的历史版本按「编号@版本」区分，编号本身不因归档而重置。
