# 置信度标准

> 每份笔记必填。它回答一个朴素问题：**这条内容，我能拿它做决策吗？**
> 没有它，三年后分不清哪些被验证过、哪些只是当年随口一猜。

## 一、三档取值（禁止自造）

| 档位 | 判据（必须可核查） | 附加要求 |
| --- | --- | --- |
| `高` | 有 `conf_src` 指向库内**原始资料或研究**编号（`R-` / `S-`），**且**已由实验或事实结果验证（有 `E-`，或 `ref_experiment` 指向存在的实验） | 无 |
| `中` | 有 `conf_src` 指向库内编号，但**未经**实验/事实验证——研究结论、行业共识或合理推断 | 建议写明还缺哪类证据 |
| `低` | **无库内来源**：个人记忆、道听途说、未归档的外部二手信息、纯主观判断 | **必须**填 `conf_why`，且 `status` 不得为 `active` |

判据顺序不能倒：**先看有没有库内来源（有 → 至少中），再看有没有被验证（有 → 高）**。

## 二、三个字段

| 字段 | 必填性 | 填什么 |
| --- | --- | --- |
| `confidence` | **必填** | `高` / `中` / `低` |
| `conf_src` | 高、中档必填 | 支撑它的库内编号，多个用数组；原始资料可填采集出处（「现场访谈第 7 场」） |
| `conf_why` | **低档必填**，中档建议 | 为什么这么判断、当时依据是什么、缺什么才能升级 |

## 三、与 `status` 的联动（硬约束）

- `低` 置信度**不得**标 `active`——没被验证过的东西不能当生效知识用；
- 假设被推翻：原卡 `confidence` 保持不变，只把 `status` 改 `deprecated`，正文写明替代假设编号；
- 复审到期不会自动降级，但会被维护流程列入待办。

## 四、升级路径（唯一方向：靠证据升级）

```
低 --补库内来源--> 中 --做实验/等事实结果--> 高
```

升级时**不要**直接改原值了事，而是在正文追加一条：

```
升级记录：2026-10-17 / 新增证据 E-2026-003 / 中 → 高
```

并同步改 `confidence` 与 `conf_src`，让档位变化本身也可追溯。

## 五、体检口径

| 检查 | 级别 |
| --- | --- |
| 缺 `confidence`，或取值不在 `高/中/低` | FAIL |
| `低` 未填 `conf_why` | FAIL |
| `低` 却标 `status: active` | FAIL（自相矛盾） |
| `高` 但 `conf_src` 为空 | WARN |

## 六、反例

| 反例 | 为什么错 |
| --- | --- |
| 全部笔记都写 `高` | 等于没有置信度 |
| `低` + `active` | 把猜测当生效知识用 |
| `confidence: 很高` | 自造档位，统计失效 |
| 升级只改数字不写升级记录 | 变化不可追溯 |
