# 标签体系

> 三层标签怎么打、哪些词能用，以本文为准。

## 一、为什么要分三层

标签任由各人随手输入，三个月后必然变成垃圾堆：同义词并存、大小写混写、中英混排。
所以把标签拆成三层——**第一层树状强分类，第二层场景角色，第三层特征属性**，
树与网结合，既能整块定位，又能多维过滤。

## 二、三层定义与落点

| 层 | 名称 | 结构 | frontmatter 键 | 取值 |
| --- | --- | --- | --- | --- |
| L1 | 业务分类树 | 树状，**互斥单选** | `l1` | 单值字符串，必须来自已登记词表 |
| L2 | 场景与角色 | 网状，多选 | `l2` | 数组，可为空 |
| L3 | 特征与属性 | 自由维度，多选 | `l3` | 数组，可为空 |

- 正文里可以额外写 `#标签` 做补充，但**三层主标签以 frontmatter 为准**；
- 新建词必须先登记进 `schema.tags` 对应层，再使用；
- 禁止：同义词并存（「客户」与「顾客」）、大小写混写、中英混排指同一概念。

## 三、各层怎么取值

### L1（互斥单选）

按知识库主目录的资产角色或业务线取一个，**不要用主题细分**——主题交给 L2/L3。
本库基线：

| L1 取值 | 对应目录 |
| --- | --- |
| 系统/首页、系统/规范、系统/模板、系统/目录说明、系统/索引 | `00_系统与索引` |
| 待加工/收件箱 | `01_收件箱` |
| 资料/一手、资料/二手、资料/现场、资料/竞品 | `02_原始资料库` |
| 研究/数据、研究/行业、研究/用户、研究/竞争、研究/经营、研究/专题 | `03_研究与洞察` |
| 思考/问题、思考/想法、思考/推理、思考/假设 | `04_思考与假设` |
| 验证/方案、验证/实验、验证/证据、验证/结论 | `05_验证与证据` |
| 知识/卡片、知识/框架、知识/模型、知识/方法、知识/流程 | `06_知识与模型` |
| 素材/文字、素材/视觉、素材/影音、素材/品牌、素材/组件 | `07_素材与组件` |
| 作品/内容、作品/产品、作品/交付、作品/营销、作品/作品集 | `08_作品与成果` |
| 运营/项目、运营/日常、运营/团队、运营/目标、运营/流程 | `09_项目与运营` |
| 复盘/决策、复盘/阶段、复盘/项目、复盘/专题、复盘/经验 | `10_决策与复盘` |
| 能力/SKILL、能力/调用记录 | `11_岗位技能库` |
| 归档/项目、归档/知识、归档/版本、归档/资料 | `12_归档与历史` |

### L2（多选：谁在什么场景用）

- 角色：`销售经理`、`实施顾问`、`前端研发`、`内容运营`、`管理者`、`新员工`；
- 场景：`招投标`、`竞品对比`、`突发事故应急`、`新员工入职培训`、`客户复盘`、`季度规划`。

### L3（多选：形态 / 阶段 / 实体关键词）

- 形态：`SOP手册`、`代码片段`、`交付模板`、`避坑指南`、`案例`、`清单`、`音视频`；
- 阶段：`售前`、`交付中`、`维护期`；
- 实体关键词：产品型号、技术栈、法规代码（`GDPR`、`ISO27001`）。

## 四、打标签的操作顺序

1. 先判**主目录**——这份内容是什么资产（唯一）；
2. 再定 `l1`——与主目录对应，只能一个值；
3. 再问「谁在什么场景会用」——填 `l2`；
4. 最后补「形态/阶段/实体」——填 `l3`；
5. 新词先登记再使用，登记处是 `vault.json.schema.tags`。

## 五、反例

| 反例 | 为什么错 |
| --- | --- |
| `l1: [客户, 交付]` | L1 只能一个值，互斥 |
| `l1: 客户 / 顾客` | 同义词并存，检索分裂 |
| 主题词全塞进 `l3` | 失去强分类，退回标签垃圾堆 |
| 标签写在正文 `#` 里就算 | 机器只信 frontmatter |
